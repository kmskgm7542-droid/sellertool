# 콜 검증 성적표 웹페이지 — 기획서

작성 2026-09-28. 대상: 대표(단독 사용자). 상태: **B안(호스팅) 확정·구현 완료** (2026-09-28, 대표 결정). 구현 내용은 README "성적표 웹페이지" 절 참고. 아래 A안 설명은 비교 기록으로 남긴다.

## 1. 목적과 원칙

주간 텔레그램 성적표는 "이번 주 숫자"만 보여준다. 웹페이지는 **누적 흐름**을 보여준다. 자산 곡선, 판정 기준 대비 진척, 콜별 결과, 주차별 변화, 채널별 성적. 목적은 하나다. **체결 50건이 쌓였을 때 합격/불합격을 한눈에 보고, 그 전에는 실거래 유혹을 막는 것.**

지켜야 할 원칙(기존 규칙 그대로):

- 콜 원문(유료 콘텐츠)·시세·결과는 레포에 커밋하지 않는다. 페이지도 `data/` 안에서 생성된다.
- 본인 검증용. 페이지에 링크를 공개하거나 재배포하지 않는다.
- 규칙(`config.mjs`)은 결과를 본 뒤 바꾸지 않는다. 페이지는 **보기만** 한다. 규칙 편집 기능은 넣지 않는다.
- ⛔ 워크포워드 합격 전 실거래 금지. 페이지 상단에 항상 고정 표시한다.

## 2. 어디에 띄울 것인가 (핵심 결정)

| 안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A. 로컬 단일 HTML (권장, 1단계)** | `weekly_run.bat` 이 `data/site/index.html` 한 파일을 만든다. 더블클릭으로 열고, 같은 파일을 텔레그램 봇으로 보내 폰에서도 연다 | 서버·계정·비용 0. 유료 콘텐츠가 PC 밖으로 안 나감(텔레그램 본인 채팅 제외). 오늘 만들 수 있음 | 실시간 아님(주 1회 + 수동 실행). URL 없음 |
| B. 호스팅 (2단계, 선택) | 셀러툴(Vercel)에 `/calls` 라우트 추가. PC가 `results.json` 을 비밀키로 업로드, 페이지는 비밀번호 뒤에서 표시 | 어디서나 URL로 봄 | 유료 콘텐츠가 서버(Vercel/Supabase)에 올라감 → 인증 필수. 셀러툴은 아직 Supabase 키가 없어 배포 준비부터 해야 함. 셀러(상품) 서비스와 매매 검증이 한 앱에 섞임 |
| C. navi-ev-trading 대시보드에 탭 추가 | 기존 FastAPI(`web/dashboard.py`, localhost:8765)에 `/calls` 추가 | 이미 있는 화면 | 그 대시보드는 자동매매 봇용. 검증 결과를 봇 화면 옆에 두면 "실거래로 연결"하고 싶은 유혹만 커짐. 분리 유지 |

**권장: A로 시작.** 사용자가 대표 한 명이고 열람은 주 1회다. 서버를 두면 얻는 것은 URL 하나뿐이고, 잃는 것은 보안·비용·유지보수다. 폰에서 보는 문제는 텔레그램 첨부(HTML 파일 → "브라우저로 열기")로 해결된다. 합격 판정이 나고 페이퍼 트레이딩으로 넘어가 매일 봐야 할 때 B를 검토한다.

## 3. 화면 기획 (A안, 한 페이지, 모바일 우선)

위에서 아래로 스크롤. 폰 화면 폭(360px)에서도 표가 깨지지 않게 카드형으로.

### 3-1. 상단 고정 띠
`⛔ 워크포워드 합격 전 실거래 금지` + 생성 시각 + "다음 자동 갱신: 일요일 22:00".

### 3-2. 판정 카드 (가장 크게)
- 현재 판정: **판정 불가 / 불합격 / 합격** 중 하나, 색으로 구분(회색/빨강/초록).
- 합격 기준 5개를 게이지로: 체결 수(10/50), 기대값(>0), t값(1.35/2.0), PF(3.85/1.3), MDD(−4.7%/−15%). 통과한 항목은 초록 체크, 미달은 빨강.
- 예상 도달 시점: 최근 4주 체결 속도로 "체결 50건까지 약 N주".

### 3-3. 자산 곡선 (그래프 1)
- 건당 1% 위험 복리 곡선(A안). B안(1차 목표 후 본절)은 점선으로 겹쳐 비교.
- x축 청산일, y축 자산(시작 100). 최대낙폭 구간을 옅게 칠한다.
- 그래프는 외부 라이브러리 없이 인라인 SVG로 그린다(파일 하나, 오프라인 동작).

### 3-4. 주차별 추이 (표 + 작은 막대)
매주 실행 결과를 `data/history.json` 에 누적하고 주차별로: 체결 누계, 승률, 평균 R, PF, MDD, 판정. 지난주 대비 화살표.

### 3-5. 콜 목록 (표, 필터)
- 열: 게시일, 채널, 시장(업비트/KRX), 종목, 진입 방식, 진입가, 손절가, 목표가(들), 기간, 상태(보유중/목표/손절/만료/미체결/제외), R, 순수익률, 보유일, 사유, 검토 표시(flags).
- 필터: 상태, 시장, 채널, 월. 기본 정렬 최신순.
- 행을 누르면 펼쳐져 상세: 체결 시각·가격, 청산 시각·가격, 손절 기준(TOUCH/CLOSE 1h/24h), 시각 정밀도(alert/day/week), 원문 요약은 **넣지 않는다**(유료 콘텐츠 원문 최소화. 숫자만).

### 3-6. 보유중 포지션
현재 열린 콜만 따로: 진입 후 경과일, 현재가 대비 손절·목표까지 거리(%), 만료일. 시세는 마지막 수집 시점 기준이라고 명시.

### 3-7. 채널별·시장별 비교 (표)
유튜브 회원게시판 / 텔레그램 사생팬 / 업비트 / KRX 별 체결 수, 승률, 평균 R, PF. 표본 10건 미만이면 "참고용" 회색 처리.

### 3-8. 검토 필요 목록
`pending_review.txt` 내용. 목표가·종목 미확정 콜. "채널이 보완하면 다음 주 자동 반영" 문구.

### 3-9. 규칙·비용 요약 (접힘)
`config.mjs` 의 RULES/COSTS/CRITERIA 를 읽어 표로. 편집 불가.

## 4. 데이터 설계

`run.mjs sim` 이 지금 만드는 report.md/results.csv/summary.txt 에 더해 **`data/results.json`** 을 만든다. 페이지는 이 파일 하나만 읽는다(빌드 시 인라인 삽입).

```
{
  "generatedAt": "2026-09-28T13:48:00+09:00",
  "verdict": { "status": "INCONCLUSIVE|FAIL|PASS", "criteria": { "filled": {"value":10,"need":50,"pass":false}, ... }, "needMore": 22 },
  "stats": { "A": {...}, "B": {...} },              // count, winRate, meanR, tStat, PF, MDD, sumNet
  "equity": { "A": [{"t":"2026-09-08","v":102.9}], "B": [...] },
  "calls": [ { "id":"s01", "postedAt":"...", "channel":"yt|tg", "market":"KRX|UPBIT", "symbol":"...", "name":"...",
               "mode":"MARKET|LIMIT|BREAKOUT", "entry":..., "sl":..., "tps":[...], "horizonDays":..., "stopBasis":"TOUCH|CLOSE_1H|CLOSE_24H",
               "status":"FILLED|OPEN|UNFILLED|SKIPPED|NO_DATA", "fill":{"t":"...","p":...}, "exit":{"t":"...","p":...,"reason":"TP|SL|EXPIRE|DATA_END"},
               "R":..., "net":..., "holdDays":..., "flags":[...], "precision":"alert|day|week" } ],
  "open": [ { "id":"...", "last":..., "toSL":-0.031, "toTP":0.082, "expiresAt":"..." } ],
  "byGroup": { "channel": {...}, "market": {...} },
  "pending": [ { "t":"...", "name":"...", "why":"목표가 없음" } ],
  "rules": { ...config.mjs... }
}
```

`data/history.json` 은 실행마다 한 줄 추가: `{ "week":"2026-W39", "generatedAt":..., "stats":..., "verdict":... }`. 같은 주에 두 번 돌면 덮어쓴다.

## 5. 구현 계획 (A안)

| 단계 | 작업 | 산출물 | 예상 |
|---|---|---|---|
| 1 | `run.mjs sim` 에 `results.json` 출력 추가(기존 계산 재사용, 새 계산 없음). `history.json` 누적 | run.mjs 수정 | 반나절 |
| 2 | `build_site.mjs`: `results.json` + `history.json` 을 읽어 단일 `data/site/index.html` 생성. 템플릿은 `site/template.html`(레포에 커밋, 데이터 없음). 그래프는 인라인 SVG | 새 파일 2개 | 1일 |
| 3 | `weekly_run.bat` 에 `node build_site.mjs` 추가. `notify.py` 가 `index.html` 도 첨부(텔레그램 "브라우저로 열기"로 폰 열람). 바탕화면 바로가기 `성적표.url` 생성 | bat/py 수정 | 1시간 |
| 4 | 가상 데이터로 화면 검증(`selftest.mjs` 결과를 `results.json` 형태로 넣어 렌더링). 폰 폭 확인 | 셀프테스트 확장 | 반나절 |
| 5 | 대표 PC에서 `weekly_run.bat` 수동 1회 → 텔레그램으로 HTML 도착 확인 → 완료 | — | — |

총 2~3일. 2단계 템플릿은 Next.js 와 무관한 순수 HTML/CSS/JS 라 셀러툴 빌드에 영향 없음.

## 6. 완료 기준

- 더블클릭 한 번(또는 텔레그램 첨부 열기)으로 3-1~3-9 가 다 보인다. 인터넷 없이 열린다.
- 텔레그램 성적표 숫자와 페이지 숫자가 일치한다(같은 `results.json`).
- 레포 커밋에 종목명·가격·콜 내용이 한 글자도 없다(`git grep` 으로 확인).
- 매주 일요일 22:00 이후 `data/site/index.html` 갱신 시각이 바뀐다.

## 7. 넣지 않는 것 (범위 밖)

- 실시간 시세, 자동 주문 버튼, 거래소 연결. 검증 도구는 검증만 한다.
- 규칙·비용 편집 UI. 규칙 변경은 `config.mjs` + README 변경 기록으로만.
- 콜 원문 표시. 숫자와 종목명까지만.
- 외부 공개 URL. B안으로 갈 때도 비밀번호 필수.

## 8. B안(호스팅)으로 갈 때의 조건과 설계 요약

조건: 합격 판정 후 페이퍼 트레이딩 단계로 넘어가 매일 봐야 할 때.
설계: 셀러툴과 분리한 새 Next.js 앱(또는 정적 사이트) + Vercel. PC의 `weekly_run.bat` 이 `results.json` 을 `POST /api/ingest`(헤더 비밀키)로 올리고 Vercel Blob에 저장. 페이지는 단일 비밀번호(env) 로그인 뒤 표시, `robots: noindex`. 비밀키·비밀번호는 PC의 `data/` 와 Vercel env 에만 둔다.
