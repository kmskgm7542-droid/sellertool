# 콜 검증기 (call-verify)

유료 멤버십 채널이 제공하는 스윙 콜(진입가·손절가·목표가·예상기간)을 **기계적으로 그대로 따랐을 때** 비용 반영 후 수익이 남는지 판정한다. 의존성 없음, Node 22 이상.

## 사용 범위와 안전장치

- 대표 본인이 정당하게 구독해 받은 콜을 **본인 매매 판단용으로만** 검증한다.
- `data/` 폴더(콜 원문·시세·결과)는 `.gitignore` 대상이다. **콜 원문은 레포에 커밋하지 않는다.** 보고서(`data/report.md`)에는 집계 수치만 남는다.
- 콜의 재배포, 상품화, 외부 공개는 하지 않는다.
- ⛔ 검증 합격 전 실거래 금지.

## 주간 자동 루틴 (대표 PC, 1회 설정 후 무인)

```
schedule_weekly.bat   # 1회 더블클릭: Node 설치(없으면) → 봇 토큰 입력 → 매주 일요일 22:00 작업 등록 → 시험 실행
```

이후 매주 일요일 밤 `weekly_run.bat` 이 자동으로 아래를 순서대로 돌리고, 결과를 **텔레그램 봇으로 대표에게** 보낸다(본문 = `data/summary.txt`, 첨부 = `data/report.md`). 업로드나 수동 작업은 없다.

```
yt_posts.py → tg_collect.py → run.mjs parse data/yt_result.json → run.mjs merge
  → fetch_prices.py → run.mjs sim → notify.py          (로그: data/weekly.log)
```

- `merge` 는 기존 `data/ledger.csv` 행을 그대로 두고 **새 콜만** 추가한다(같은 종목·같은 손절가·±2일은 중복으로 봄). 가격이 불완전한 콜은 `data/pending_review.txt` 에 남기고 원장에는 넣지 않는다.
- 유튜브 게시글 시각은 같은 날의 사생팬 알림(텔레그램) 시각으로 바꿔 넣는다(`precision=alert`). 하루 어긋날 수 있어 `시각=사생팬 알림` 표시를 남긴다.
- 매일 21:30 `CallVerifyDaily`(`schedule_daily.bat`)는 그대로 둔다. 매일 수집해야 유튜브 게시글이 **하루 이내 정밀도**로 쌓인다. 일요일에는 두 작업이 30분 간격으로 돌지만 수집은 증분이라 문제 없다.
- 봇: `navi-ev-trading` 에서 쓰던 BotFather 봇 토큰을 그대로 쓴다. 토큰은 `data/tg_bot.json`(gitignore) 에만 저장한다. 봇은 먼저 말을 걸 수 없으므로 대표가 그 봇에게 한 번은 메시지를 보낸 상태여야 한다. 재설정은 `setup_bot.bat`.
- 해제: `schtasks /delete /tn CallVerifyWeekly /f`

### 방송 타점 직접 기록 (`schedule_live.bat`, `live.mjs`)

방송(평일 14:50~15:00 시작, 시황 30분 뒤 개별 종목)에서 나온 타점은 게시판·알림에 안 올라오는 경우가 있다. 방송을 **보는 사람이 그 자리에서** 텔레그램 봇(성적표 보내는 그 봇)에 한 줄로 보내면, PC가 즉시 해석해 확인 답장을 주고 `data/live_calls.json` 에 쌓는다. 시각은 텔레그램 서버 시각(정확). 방송 음성·자막을 자동으로 받아 적는 방식은 쓰지 않는다(정확도·시각 불명확·저작권).

```
형식: 종목 [진입가|현재가] 매수 손절 N 목표 N [N] [기간] [손절기준]
예:   삼성전자 7만 매수 손절 6.8만 목표 7.5만 8만 2주
      에코프로 현재가 매수 손절 12만 목표 15만 일봉종가
      비트코인 9500만 아래 매수 손절 9000만 목표 1억 1주 1시간종가
취소: "취소" 또는 "취소 <종목>"
```

- 첫 단어가 종목명(확정). 나머지는 게시판 콜과 같은 파서로 해석한다. 진입·손절·목표 중 하나라도 없으면 기록은 되지만 검증 제외(❌ 답장).
- `schedule_live.bat` 1회 실행 → 평일 14:40부터 130분간 `CallVerifyLive` 작업이 대기하며 즉시 답장. 그 밖의 시간에 보낸 메시지는 매일 21:30·매주 배치가 밀린 것을 처리한다(텔레그램 보관 24시간 안이면 시각 그대로).
- 주간 배치가 `run.mjs parse data\live_calls.json → merge` 로 원장에 넣는다. 같은 콜이 나중에 게시판에도 올라오면 중복(같은 종목·손절가·±2일)으로 걸러진다.
- 국내주식은 방송 시각이 대개 장 마감 무렵이다. 15:20 이후 콜은 **다음 거래일 시가** 체결로 본다(규칙 `dailyFillCutoffHours`).

### 방송 자막 자동추출 (`yt_live.py` → `extract_rules.mjs`, 매일 21:30 자동, 무료)

직접 기록을 놓쳐도 되게, 방송이 끝난 뒤 유튜브 다시보기의 **한국어 자막(자동 생성)** 을 받아 타점을 뽑는다. 뽑힌 콜은 `종목 진입 매수 손절 N원 목표 N원 기간` 한 줄로 바꿔 `live_calls.json` 에 넣고(시각 = 방송 시작 시각 + 자막 오프셋, 정확), 채널 "방송(자동추출)" 로 집계한다. 텔레그램으로 요약이 오며 틀린 건 `취소 <종목>` 으로 지운다.

- `yt_live.py`: 채널 실시간 탭 → 최근 방송 → `ytInitialPlayerResponse` 의 자막 트랙(ko, asr 허용) → `data/live_vod/<id>.json`. 방송 중이면 건너뛰고, 자막이 아직 없으면 3일간 재시도.
- `extract_rules.mjs`(기본, 무료): 종목 사전(코스피·코스닥 3자 이상 + 업비트 전체 + 별칭 "리플→엑스알피(리플)")에 있는 이름이 나온 지점마다 앞 2·뒤 8구간(다른 종목 이름이 나오면 거기서 자름)을 창으로 잡고, 말투("사도 돼요"→매수, "깨지면 나가"→손절, "손절 6만 8천"→"6만 8천 손절")를 콜 표기로 바꾼 뒤 게시판 콜 파서로 해석한다. 진입 표현 + (손절 또는 목표 숫자)가 있어야 후보. 두 글자 주식명(기아·한화 등)은 일상어와 겹쳐 자동 인식하지 않는다(직접 기록으로 보완).
- `extract_calls.py`(선택, 유료): `setup_ai.bat` 으로 Claude API 키(`data/anthropic.json`)를 넣으면 규칙 대신 Claude(`claude-opus-5`, 방송 1회당 약 100~300원)가 12분 구간 구조화 출력으로 추출한다. 자막 오인 보정력이 더 좋다. 키 파일이 있으면 배치가 자동으로 이쪽을 쓴다.
- 한계: 자동 자막은 종목명·숫자를 틀릴 수 있다. 자동추출 콜은 `flags` 에 "시장·종목코드 입력 필요" 가 남으면 검토 필요로 분류되므로 성적표의 검토 목록을 주 1회 본다. 직접 기록(`live.mjs`)이 있으면 같은 콜은 중복으로 걸러진다.
- 자막·추출물은 `data/` 에만 두고 재배포하지 않는다. 채널 전체 영상을 내려받거나 기법을 재구성하는 용도로 쓰지 않는다(콜 숫자 검증만).
- 지금 한 번 돌려보기: `live_vod.bat`.

### 성적표 웹페이지 (`/calls`, 비밀번호 보호)

`run.mjs sim` 이 `data/results.json`(웹용 스냅샷, 콜 원문 없음)을 만들고, `publish.py` 가 셀러툴 앱의 `POST /api/calls/ingest` 로 올린다. 서버는 Vercel Blob **비공개** 블롭에 최신본과 주차별 요약을 저장하고, `/calls` 페이지는 비밀번호(쿠키 30일) 뒤에서 판정 카드·자산 곡선·주차 추이·콜 목록·보유중·채널별·검토 필요·규칙을 보여준다. 색인 금지(noindex).

1회 설정: Vercel 프로젝트에 환경변수 `CALLS_PASSWORD`(페이지 비밀번호), `CALLS_INGEST_KEY`(업로드 키) 와 Blob 저장소 연결(`BLOB_STORE_ID` 또는 `BLOB_READ_WRITE_TOKEN` 자동 등록) → Redeploy → PC에서 `setup_site.bat`(주소·키를 `data/site.json` 에 저장, 연결 확인, 첫 업로드). 이후 `weekly_run.bat` 이 매주 자동 업로드하고 텔레그램 성적표에 링크를 붙인다. 코드: `app/calls`, `app/api/calls/ingest`, `lib/calls`, `components/calls`, 테스트 `__tests__/calls.test.ts`.

## 수동 흐름 (클라우드 또는 PC 개별 실행)

```
node run.mjs parse data/result.json      # 1) 텔레그램/유튜브 수집물 → data/ledger.draft.csv
node run.mjs merge                       #    초안을 data/ledger.csv 에 병합(새 콜만)
#   사람이 flags 열을 검토 (market/symbol 확인, ok=1)
python fetch_prices.py                   # 2) 시세 수집 → data/prices/ (+ prices.zip). 클라우드에서는 node run.mjs fetch
node run.mjs sim                         # 3) 시뮬레이션 → data/report.md, data/results.csv, data/summary.txt
node selftest.mjs                        # 규칙 자체 검증(가상 데이터, 29건)
```

입력은 텔레그램 데스크톱의 "대화 내용 내보내기(JSON)" `result.json`, 또는 빈 줄로 구분하고 첫 줄에 `YYYY-MM-DD HH:MM`(KST)을 적은 텍스트 파일. 채널이 여러 개면 메시지의 `channel` 필드로 구분되며 보고서에 채널별 집계가 따로 나온다.

### 직접 수집 (`tg_collect.bat`, 대표 PC에서 실행)

텔레그램 데스크톱 내보내기 대신, 본인 계정으로 로그인해 채널 글을 자동으로 내려받는다. 이 클라우드 환경은 텔레그램 서버에 접근할 수 없으므로 수집은 **PC에서** 하고, 결과 파일만 올린다(`navi-ev-trading/hub`의 "로컬이 수집, 클라우드가 분석" 방식).

1. 1회 준비: https://my.telegram.org 로그인 → **API development tools** → 아무 앱 이름으로 생성 → `api_id`, `api_hash` 확인
2. `tg_collect.bat` 더블클릭 → api_id/api_hash 입력(첫 회) → 전화번호·인증코드 입력(첫 회) → 채널 번호 선택(첫 회)
3. 이후 실행은 로그인·채널 선택 없이 **새 글만 증분 수집** → `data/result.json` 갱신
4. `data/result.json` 을 김이사에게 업로드 (또는 PC에서 `node run.mjs parse data/result.json`)

`data/tg_session.session` 은 로그인 정보이므로 외부에 공유하지 않는다. 채널을 바꾸려면 `data/tg_config.json` 의 `channels` 를 지우고 다시 실행한다. 글자 없는 사진 알림은 `data/tg_media/` 에 저장된다(나중에 글자 추출용).

### 유튜브 회원 게시판 수집 (`yt_posts.bat`, 대표 PC에서 실행)

콜의 본문(진입·손절·목표·기간)은 유튜브 채널 게시판의 회원 전용 글에 올라오고, 텔레그램은 알림 역할이다. 그래서 게시판을 직접 읽는다.

1. `yt_posts.bat` 더블클릭 → 첫 실행은 브라우저(Chromium) 다운로드 2~3분
2. 채널 주소 입력(첫 회) → 브라우저 창이 열리면 **멤버십 구글 계정으로 유튜브 로그인** → 검은 창에서 Enter (첫 회)
3. 게시판을 자동으로 스크롤해 글을 모은다 → `data/yt_result.json`
4. `node run.mjs parse data/yt_result.json` 또는 김이사에게 업로드

유튜브는 "5일 전" 같은 상대 시각만 보여주므로, **처음 본 시점에 역산한 시각**을 저장하고 이후 갱신하지 않는다. `date_precision` 이 `week` 이상이면 진입 시점 판정에 쓰기 어려우니 검토 표시가 붙는다. **매일 한 번 실행**하면 새 글은 하루 이내 정밀도로 쌓인다. 텔레그램 알림 시각(정확)과 게시글을 맞춰 보정하는 단계는 자료가 쌓인 뒤 추가한다.

시세: 코인은 업비트 1시간봉(`api.upbit.com`), 국내주식은 네이버 일봉(`fchart.stock.naver.com`). 이 클라우드 환경에서는 두 도메인이 네트워크 허용 목록에 있어야 한다.

## 사전 확정 규칙 (`config.mjs`)

결과를 본 뒤 규칙을 바꾸지 않는다. 바꿔야 하면 아래 변경 기록에 이유와 함께 남긴다.

| 구분 | 규칙 |
|---|---|
| 진입 | 진입가가 게시 직전 가격의 ±1% 이내면 다음 봉 시가에 매수. 아래면 지정가(저가 도달 시), 위면 돌파(고가 도달 시). 게시 후 5일 안에 미도달 → 미체결 |
| 손절 기준 | 콜에 명시된 기준을 따른다. "1시간 종가" → 1시간봉 종가 이탈, "일봉 종가" → 일봉 종가 이탈(코인은 KST 09시 마감) 시 다음 봉 시가 청산. 기준이 없으면 봉 중간 터치 시 손절가 청산(보수적) + 검토 표시 |
| 목표가 | 봉 중간 터치. 여러 개면 균등 분할. 범위("19천~2만")는 하단 적용. 같은 봉에서 목표·손절 동시 도달 → 손절 우선 |
| 기간 | 명시값. "단기" 7일, "중기" 30일, "장기" 90일, 이벤트 기준("추석 이후") 14일, 없으면 14일. 만료 시 종가 청산 |
| 제외 | 체결 시점에 이미 손절가 이하이거나 1차 목표 이상이면 매매 제외(SKIPPED) |
| 일봉 데이터 특례 | 국내주식은 일봉만 있으므로, 장중(15:20 KST 이전)에 게시된 "현재가 매수"는 **그날 종가에 체결**한 것으로 본다(`MARKET_CLOSE`). 15:20 이후 게시는 그날 체결 불가 → 기준가는 그날 종가, 체결은 다음 거래일부터. 그날 종가가 이미 손절가 아래면 **당일 손절**로 세고, 체결가는 손절가 +1%로 근사한다(`SL_SAMEDAY`, ≈ −1R). "N시간 종가" 손절 기준은 일봉 데이터에서는 일봉 종가로 근사한다 |
| 비용 | 업비트 편도 0.15%(수수료 0.05% + 슬리피지 0.1%). 국내주식 매수 0.215%, 매도 0.415%(거래세 포함). 세율 변경 시 `COSTS` 수정 |
| 사이징 | 손절 시 계좌의 1% 손실로 고정. 자산 곡선과 최대낙폭은 이 기준의 복리 |

A안은 처음 제시된 목표가·손절가를 그대로 적용한다. B안(비교용)은 1차 목표 도달 후 손절가를 진입가로 옮긴다. 채널의 사후 관리가 가치를 더하는지 보는 용도이며, 판정은 A안으로 한다.

## 합격 기준 (전체 콜 기준, 골라내기 금지)

체결 50건 이상 · 기대값 > 0 · t값 ≥ 2 · PF ≥ 1.3 · 최대낙폭 ≥ −15%. 하나라도 미달이면 불합격, 표본 부족이면 판정 불가. 합격 후에도 4~8주 전향적 확인 → 페이퍼 트레이딩 → 소액 실거래 순서를 지킨다.

## 알려진 한계

- 봉 안의 가격 순서는 알 수 없다. 동시 도달은 손절 우선, 돌파 체결 봉에서는 익절을 세지 않는 보수적 처리를 한다.
- 슬리피지는 고정 비율이다. 소형 종목이나 큰 주문에서는 실제가 더 나쁠 수 있다.
- 파서는 자유 문장을 다루므로 완벽하지 않다. `flags` 열이 비어 있지 않은 행은 반드시 사람이 확인한다.
- 주봉 종가 기준 손절은 지원하지 않는다(일봉 종가로 대체하고 표시).
